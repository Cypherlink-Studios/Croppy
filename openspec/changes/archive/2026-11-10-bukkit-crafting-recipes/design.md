# Design

## Context

Croppy maintains strict hexagonal boundaries between pure domain models (`croppy-api`), core business logic and serialization (`croppy-core`), and Paper 1.21.8+ platform adapters (`croppy-paper`). Custom items are instantiated through `ItemFactory`, carrying `croppy:item_id` and `croppy:category` PersistentDataContainer (PDC) tags, localized MiniMessage names, and native `item_model` components.

Culinary station cooking is handled by `RecipeRegistry` and `ProcessEngine` (using `recipes/` YAMLs with station and temperature dependencies). Bukkit vanilla crafting table recipes (`ShapedRecipe`, `ShapelessRecipe`) require a separate registration pipeline, lifecycle tracking, and ingredient choice conversion that respects custom PDC tags and vanilla tags.

## Goals / Non-Goals

**Goals:**
- Provide pure Java 21 domain records for shaped and shapeless crafting recipes in `croppy-api`.
- Implement declarative YAML loading and registry management in `croppy-core` (`crafting/**/*.yml`).
- Implement Bukkit recipe registration, unregistration on reload, and ingredient resolution (`MaterialChoice` vs `ExactChoice`) in `croppy-paper`.
- Integrate recipe auto-discovery into the vanilla recipe book via `config.yml`.
- Expose `CraftingRecipeRegistry` to the Addon System and support declarative `crafting/` directory discovery.
- Bundle starter recipes for cooking stations (`stove`, `cooking_pot`, `skillet`), tools (`inspector`, `thermometer`), and tiered watering cans.

**Non-Goals:**
- Non-crafting table vanilla recipe types (Furnace, Blasting, Smoker, Campfire, Stonecutter, Smithing) in phase 1.
- Replacing or modifying the culinary station recipe engine (`recipes/` and `ProcessEngine`).
- Dynamic runtime recipe modification in-game via GUI.

## Decisions

### 1. Dedicated `crafting/` Directory Structure
- **Decision**: Store all Bukkit crafting recipes in `plugins/Croppy/crafting/**/*.yml` (e.g., `crafting/stations/`, `crafting/tools/`, `crafting/watering_cans/`).
- **Rationale**: Keeps item definition files (`items/`) focused solely on item metadata, models, and PDC. Allows multiple alternative crafting recipes for the same item result, and permits recipes that output vanilla items from Croppy ingredients.
- **Alternatives Considered**:
  - *Inline in `items/*.yml`*: Bloats `ItemDefinition` record and prevents alternate recipes.
  - *Subdirectory under `recipes/` (e.g. `recipes/crafting/`)*: Risk of confusion with existing culinary station recipes (`recipes/*.yml`).

### 2. Dual Ingredient Resolution: `MaterialChoice` vs `ExactChoice`
- **Decision**: Resolve ingredient keys dynamically in `croppy-paper`:
  - `minecraft:<material>` -> `new RecipeChoice.MaterialChoice(Material.valueOf(...))`
  - `#minecraft:<tag>` -> `Bukkit.getTag("items", NamespacedKey)` -> `MaterialChoice`
  - `croppy:<item_id>` -> `new RecipeChoice.ExactChoice(itemFactory.createItemStack(itemDef, 1))`
- **Rationale**: Vanilla materials must accept any vanilla item stack without requiring synthetic PDC tags. Croppy custom items MUST use `ExactChoice` to ensure players cannot use arbitrary vanilla items renamed on an anvil.
- **Alternatives Considered**:
  - *Custom Crafting Listener (`PrepareItemCraftEvent`)*: More complex and interferes with native client-side recipe book preview and Shift-click crafting. Native Bukkit `RecipeChoice` works cleanly with client prediction.

### 3. Lifecycle Tracking & Clean Unregistration
- **Decision**: `PaperCraftingRecipeService` maintains a thread-safe `Set<NamespacedKey> registeredKeys`. On plugin disable or reload (`/croppy reload`), it calls `Bukkit.removeRecipe(key)` for each registered key before clearing the registry and reloading.
- **Rationale**: Paper's server recipe manager retains registered recipes in memory. Failing to remove them leads to duplicate recipe warnings or stale recipes upon configuration reloading.

### 4. Configurable Recipe Book Auto-Discovery
- **Decision**: Add `crafting.auto-discover-recipes: true` in `config.yml`. When enabled, a `PlayerJoinEvent` listener calls `player.discoverRecipes(registeredKeys)`.
- **Rationale**: Minecraft 1.21+ supports recipe book auto-discovery. Server admins who prefer natural vanilla discovery progression can toggle this off.

## Risks / Trade-offs

- **[ExactChoice Strictness]** Custom items in `ExactChoice` require exact metadata match (name, lore, PDC, custom model).
  - *Mitigation*: Ingredients in recipes should use standard base items generated by `ItemFactory.createItemStack(def, 1)` without dynamic durability or lore modifications.
- **[Reload Recipe Desynchronization]** Calling `Bukkit.removeRecipe` on active servers may leave open crafting inventories in an inconsistent visual state.
  - *Mitigation*: Unregistration occurs synchronously during server reload commands; Bukkit automatically recalculates open inventory matrices on next tick.
- **[Missing Ingredient Dependency]** A recipe might declare a `croppy:*` ingredient or result that is not yet loaded or belongs to an unloaded addon.
  - *Mitigation*: `YamlCraftingRecipeLoader` validates basic syntax, and `PaperCraftingRecipeService` performs deferred resolution against `ItemRegistry`, logging clear warnings and skipping unresolvable recipes without crashing.

## Migration Plan

1. No breaking changes to existing data or persistence.
2. Default recipe YAMLs are extracted only if they do not already exist in `crafting/`.
3. Existing survival worlds will immediately gain access to crafting recipes upon server startup or reload.
