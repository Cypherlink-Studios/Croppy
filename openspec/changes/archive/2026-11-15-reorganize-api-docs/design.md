# Design

## Context

See [proposal.md](./proposal.md) for motivation. Currently, all 22 Markdown documents per locale (`docs/en/*.md` and `docs/es/*.md`) sit flat under each language directory with frontmatter `sidebar.order` values `1..22`. Java API details (`CroppyAddon`, `AddonContext`, `PaperAddonContext`, `AddonClassLoader`, `VariableProvider`, `DataType<T>`, `TypedVariableStore`, `ExpressionCompiler`, `ProtectionPort`, `EconomyPort`, `TranslationProvider`, `GrowthModifier`) are embedded across six administrator/YAML guides (`addon-system.md`, `workstations-configuration.md`, `rules-and-interactions.md`, `integrations.md`, `localization.md`, `growth-and-environment.md`), while `croppy-api` exposes 17 packages (~143 Java files) whose core developer contracts (`AddonConfig`, `CroppyLogger`, `Registry<T>`, `EvaluationContext`, `OperationArgs`, growth interceptors) lack dedicated reference documentation.

External ingestion by the Starlight portal (`DarkBladeDev-plugins`) was audited:
- `extractDocsFromTarball` and `syncLocalDocs` (`copyDirRecursive`) in `src/loaders/github-docs-loader.ts` already extract/copy nested subdirectories recursively into `src/content/docs/<lang>/docs/<pluginId>/...`.
- `src/content.config.ts` (`glob` pattern `**/[^_]*.{...}`) and `src/plugins/remark-rewrite-markdown-links.ts` (`path.posix.resolve` relative to `currentDir`) already resolve nested routes like `/<lang>/docs/croppy/api/<slug>/` and relative links (`./api/...`, `../...`).
- `src/components/starlight/Sidebar.astro` filters groups recursively and distinguishes version folders via `isVersionSlug` (`/^v?\d+.../`), so an `api/` directory is preserved as a nested group rather than treated as a version slug.
- **Gap identified**: `validateDocSlugs` in `src/loaders/github-docs-loader.ts` uses a non-recursive `fs.readdirSync` filtered only by `.md`/`.mdx`, so mismatched filenames inside `docs/<lang>/api/` are not checked for ES/EN slug parity. Additionally, Starlight autogenerated sidebar groups render the raw directory name (`api`) unless mapped in `Sidebar.astro`.

## Goals / Non-Goals

**Goals:**
- Separate administrator/YAML configuration guides (`docs/<lang>/*.md`) from Java developer documentation (`docs/<lang>/api/*.md`) using a modular 5-page layout (`index`, `addon-development`, `typed-variables`, `expressions-and-providers`, `ports-and-registries`).
- Maintain strict 1:1 filename, frontmatter `sidebar.order`, and content parity between `docs/en/api/` and `docs/es/api/` as well as refactored root guides.
- Document previously undocumented `croppy-api` contracts (`AddonConfig`, `CroppyLogger`/`LogChannel`/`LogLevel`, `Registry<T>` and the 12 registries on `AddonContext`, `EvaluationContext`/`Expression`/`VariableResolver`, `OperationArgs`, growth hooks) strictly grounded in the current source code.
- Ensure `DarkBladeDev-plugins/src/loaders/github-docs-loader.ts` validates recursive slug parity (ignoring version directories at the plugin root) before nested docs are published.

**Non-Goals:**
- Changing any Java runtime API, package, or behavior in `croppy-api`, `croppy-core`, or `croppy-paper`.
- Generating full automated Javadoc HTML sites (the `api/` section provides curated, task-oriented developer guides and contract references).
- Modifying archived historical documentation snapshots (`v0.2.0`..`v0.9.1`).

## Decisions

### 1. Five-page modular split under `docs/<lang>/api/`
- **Decision**: Organize `docs/<lang>/api/` into 5 focused pages with explicit `sidebar.order` (`1..5`):
  1. `index.md` — Hexagonal overview, Gradle dependency (`dev.darkblade.croppy:croppy-api:0.10.0`), package map, `Key`/`Keyed`, `BlockPosition`, `ChunkPosition`.
  2. `addon-development.md` — `CroppyAddon`, `AddonContext`, `AddonConfig`, `PaperAddonContext`, `AddonClassLoader` DAG, 5-phase decommissioning, dormant crops, and `growth` hooks (`GrowthModifier`, `StageAdvanceInterceptor`, `UnwateredPolicy`, `WitherHandler`).
  3. `typed-variables.md` — `DataType<T>`, `SimpleDataType<T>`, `CompoundDataType<T>`, `DataTypeRegistry`, `TypedVariableStore`, `TypedVariable<T>`, `VariableOperation<T>`, `OperationArgs`, `VariableStoreBinaryCodec`, `UnresolvedVariableData`.
  4. `expressions-and-providers.md` — `VariableProvider`, `EvaluationContext`, `Expression`, `VariableResolver`, standard component namespaces (`thermal.*`, `heat.*`, `storage.*`, `process.*`, `display.*`, `var.*`), Pratt AST grammar, and `ContextualTextFormatter`.
  5. `ports-and-registries.md` — `Registry<T>` contract, all 12 domain registries exposed on `AddonContext` + `DataTypeRegistry`, `CroppyLogger` (`LogLevel`, `LogChannel`, lazy `Supplier<String>`, `.scoped()`), and SPI ports (`ProtectionPort`, `EconomyPort`, `TranslationProvider`).
- **Alternatives considered**:
  - *Single monolithic `developer-api.md`*: Too large and hard to navigate given `croppy-api` spans 17 packages and ~143 classes.
  - *2–3 coarse pages*: Forces unrelated concerns (e.g., logging/SPI ports mixed with AST expression evaluation or binary variable codecs).
- **Rationale**: Matches Starlight's nested sidebar grouping cleanly and keeps each page cohesive by developer workflow.

### 2. Audience boundary between root YAML guides and `api/`
- **Decision**: Root guides (`addon-system.md`, `workstations-configuration.md`, `rules-and-interactions.md`, `integrations.md`, `localization.md`, `growth-and-environment.md`) retain all YAML schemas, server admin commands, gameplay rules, placeholders, and declarative pack instructions; Java interfaces, Gradle snippets, classloader graphs, and internal codecs move to `api/`, replaced by concise cross-links (`./api/<page>.md`).
- **Rationale**: Server admins configuring `stations/*.yml` or `rules/*.yml` still need `default_variables:`, `when:`, and `{var.*}` placeholder syntax inline without wading through Java serialization contracts, while Java developers get one canonical place to read `croppy-api`.

### 3. Relative Markdown link convention & Starlight compatibility
- **Decision**: Use standard relative `.md` links (`./api/addon-development.md` from root guides; `../workstations-configuration.md` and `./typed-variables.md` from inside `api/`) so `remark-rewrite-markdown-links.ts` resolves both root-relative and nested routes across `en`, `es`, and future archived versions.
- **Alternative**: Hardcoded absolute `/en/docs/croppy/api/...` URLs — rejected because they break versioned snapshots (`/vX.Y.Z/`) and locale switching.

### 4. Portal loader recursive slug validation (`DarkBladeDev-plugins`)
- **Decision**: Update `validateDocSlugs` in `DarkBladeDev-plugins/src/loaders/github-docs-loader.ts` to walk subdirectories recursively and compare relative POSIX paths (e.g., `api/typed-variables.md`), skipping root-level directories matching `isVersionSlug` so archived version folders are not cross-checked against latest root docs. Optionally map directory label `api` -> `API` in `Sidebar.astro` (or document Starlight's label behavior).

## Risks / Trade-offs

- **Portal sidebar label casing (`api` vs `API`)**: Starlight autogenerates nested group labels from directory names (`api`). → Mitigation: Either accept lowercase `api` initially or add a clean label normalization in `DarkBladeDev-plugins/src/components/starlight/Sidebar.astro`.
- **Broken cross-links during split**: Moving sections out of `addon-system.md` or `workstations-configuration.md` could leave stale anchor links in other guides. → Mitigation: Audit all Markdown links across `docs/en/` and `docs/es/` before completing tasks, and add `remark-rewrite-markdown-links` validation / portal build check if available.
- **Code-to-doc drift**: Documenting new `croppy-api` contracts risks signature typos. → Mitigation: Verify every Java package, interface, method signature, and record component directly against `croppy-api/src/main/java/...` while authoring.
- **Cross-repository dependency**: `DarkBladeDev-plugins` lives outside the `Croppy` workspace (`../MISC/DarkBladeDev-plugins`). → Mitigation: Track the portal loader update as an explicit prerequisite task before merging/deploying `docs/<lang>/api/*`.

## Migration Plan

1. Update `DarkBladeDev-plugins/src/loaders/github-docs-loader.ts` (`validateDocSlugs` recursive scan) + unit test in `github-docs-loader.test.ts` and run portal tests (`pnpm test` / `pnpm check`).
2. Author all 5 pages under `docs/en/api/` verified against `croppy-api` source files.
3. Refactor the 7 root guides under `docs/en/` to remove migrated Java/API sections, update version `0.5.7` -> `0.10.0`, harmonize legacy rule variables, and add relative links to `./api/*`.
4. Mirror the exact structure and translations into `docs/es/api/` and refactor `docs/es/` root guides.
5. Verify 1:1 file parity between `docs/en/` and `docs/es/`, validate all relative `.md` links and `sidebar.order` values, and test local portal ingestion (`syncLocalDocs` / build) if available.
